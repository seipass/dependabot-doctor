dependabot-doctor Source

Find the groups in your dependabot.yml that match nothing

If your update job logged Please check your configuration as there are groups where no dependencies match this page tells you which groups are dead — and which ones matched and still lost their dependencies to another group.

Public GitHub repo. Or paste your YAML instead →

Your config is never uploaded, and there is no account or token: this page reads public files from GitHub in your browser. If a check needs a file list or a branch list, we make one request for each, and we say so before we make it.

Nothing is stored. No sign-in.

Example: Fastjur/dependabot-group-specificity-repro — the repro repo from dependabot-core #14576, deliberately tiny.

What this cannot see

  • Whether an update is available, and its type (major/minor/patch) — we only read what is committed.
  • GitHub's behaviour inside the updater: we model the scoring in dependabot-core #13044. If Dependabot changes that scoring, we are wrong and this page is stale — check the commit date.
  • repos where the manifest is not committed (we mark those skipped rather than guess).
  • ecosystems outside the list this tool knows. That list is a subset — "not an ecosystem this tool knows" is not the same as "not valid", and if Dependabot supports one we do not, this tool is behind, not Dependabot.

Modelled from dependabot-core upstream, pattern_specificity_calculator.rb, read 2026-11-07.

What this page sends, exactly

  • To raw.githubusercontent.com: one request for .github/dependabot.yml, then one request per manifest file your config names — for npm that is package.json, package-lock.json, npm-shrinkwrap.json, yarn.lock and pnpm-lock.yaml, in the directory your config declares.
  • To api.github.com: only when your config uses a directory glob such as /packages/*, one request for the file list. We tell you before we make it.
  • Every request asks for at most the first 1 MB of a file, so a large lockfile is reported rather than half-read.
  • No cookies, no token, no referrer, no analytics, no fonts, no images, no telemetry. This page and its scripts are served from seipass.github.io, and nothing else is contacted.
  • Your config and the findings live in this tab only. Closing it clears them.

Run it locally

npx --yes github:seipass/dependabot-doctor#v0.1.2

Please check your configuration as there are groups where no dependencies match

That warning is what Dependabot prints when a group it is about to evaluate matches no dependency. The group can be empty because its patterns match nothing, because patterns is present but empty, because an ignore rule removes every match, or because a higher-scoring group took the dependencies it did match. This page separates those cases and cites the line.

dependabot groups not working

Since September 2025 the updater scores each group against a dependency and gives it to the highest score, so a group written first is not the group that wins. A group with no patterns key at all scores 500 and takes pattern matches scoring below it.

dependabot.yml ignore not working

An ignore rule that matches no dependency is silent: it blocks nothing and Dependabot does not warn about it. The finding names the rule's line and the number of dependencies the rule was compared against.

If a dependency matches more than one rule, it's included in the first group that it matches

The docs say this, and since Sept 2025 the updater does something else: it scores patterns and the highest score wins.
